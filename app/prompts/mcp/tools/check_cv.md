Check a CV for a job exactly as save_cv will, saving nothing: no version, no file, no download link. The text is checked first without rendering: unknown or unconfirmed facts, the photo, invisible characters, line breaks, tabs or double spaces inside a field, leading list markers, [placeholders]; only when the text is clean the PDF is rendered in memory and linted (pages, headings, order, extraction, fonts). The result has passed, issues, keywords (covered, missing, percent of the analysis keywords found in the text) and gate (status passed, failed or no_data; evidence_percent: the share of the keywords a confirmed fact backs that are in the text, 100 needed, evidence_missing names the rest; coverage_percent: the share of all keywords in the text, 90 needed; no_data: the analysis has no fact map, which is not a pass). Fix every issue and check again until passed is true, then call save_cv once. A missing keyword is not an issue: add it only where a confirmed fact backs it, otherwise tell the user it is a gap. A gate that is not passed does not block save_cv: show the user both numbers and the named words. Optional must_have_facts: for each must_have item of the analysis the confirmed fact_ids that answer it and kind (fact: the facts meet the requirement itself; analogue: the closest related facts, the requirement itself is a gap). The result then has must_have_coverage: per item covered, analogue or missing (with fact_ids and reason), and unknown for items not in the analysis; null when the job has no analysis or the text could not be read; without must_have_facts every item is missing. A missing item is not an issue: explain it to the user or fix the CV, never invent a fact.
